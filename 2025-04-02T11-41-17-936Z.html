Node.js Video Streaming

Let's say I want to create a video streaming server from scratch using node.js how to do that?

Creating a video streaming server from scratch using Node.js involves setting up an HTTP or WebSocket server to serve video files efficiently. Here's a step-by-step guide:

1. Choose a Streaming Method

There are two main methods for streaming videos:

  • Progressive Streaming (HTTP Streaming) – Sends video chunks via HTTP (like YouTube).

  • Adaptive Streaming (HLS, DASH) – Uses a playlist with multiple bitrates for a better experience.

For simplicity, let's start with progressive streaming.

2. Setup Your Node.js Server

You'll need express for routing and fs to read video files.

Install Dependencies 

sh
mkdir video-streaming-server
cd video-streaming-server
npm init -y
npm install express

3. Create the Server

Create an index.js file and add this code: 

javascript
const express = require("express");
const fs = require("fs");
const path = require("path");

const app = express();
const PORT = 3000;

// Serve the HTML player
app.get("/", (req, res) => {
    res.sendFile(path.join(__dirname, "index.html"));
});

// Stream video endpoint
app.get("/video", (req, res) => {
    const videoPath = "video.mp4"; // Change this to your video file
    const videoSize = fs.statSync(videoPath).size;

    const range = req.headers.range;
    if (!range) {
        return res.status(400).send("Requires Range header");
    }

    const CHUNK_SIZE = 10 ** 6; // 1MB
    const start = Number(range.replace(/\D/g, ""));
    const end = Math.min(start + CHUNK_SIZE, videoSize - 1);

    const contentLength = end - start + 1;
    const headers = {
        "Content-Range": `bytes ${start}-${end}/${videoSize}`,
        "Accept-Ranges": "bytes",
        "Content-Length": contentLength,
        "Content-Type": "video/mp4",
    };

    res.writeHead(206, headers);

    const videoStream = fs.createReadStream(videoPath, { start, end });
    videoStream.pipe(res);
});

app.listen(PORT, () => {
    console.log(`Server is running on http://localhost:${PORT}`);
});

4. Create a Simple HTML Player

Create a file named index.html in the same folder: 

html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Video Streaming</title>
</head>
<body>

    <video controls width="640" height="360">
        <source src="/video" type="video/mp4">
        Your browser does not support the video tag.
    </video>
</body>
</html>

5. Run the Server

Place a sample video (video.mp4) in the project folder and start the server: 

sh
node index.js

Visit http://localhost:3000/ in your browser to watch the streamed video.

What is the range header for?

The Range header is used in HTTP requests to enable partial content retrieval. This is essential for video streaming because it allows the client (e.g., a browser or media player) to request only specific portions of a file, rather than downloading the entire video at once.

Why is the Range header important?

  1. Efficient Streaming – The client requests only small chunks of the video, improving performance.

  2. Seamless Seeking – Allows users to skip to different parts of the video without reloading the entire file.

  3. Bandwidth Optimization – Reduces data usage, especially for large videos.

  4. Resuming Downloads – Supports interrupted downloads by fetching only the missing parts.

How It Works

When a browser plays a video, it sends an HTTP request with a Range header, asking for a specific byte range.

Example Request 

http
GET /video HTTP/1.1
Range: bytes=1000000-

This means:

  • The client wants the video starting from byte 1,000,000 to the end.

Server Response

The server does not return the entire file. Instead, it responds with: 

http
HTTP/1.1 206 Partial Content
Content-Range: bytes 1000000-2000000/5000000
Content-Length: 1000001
Content-Type: video/mp4

  • The 206 Partial Content status code tells the client that it's getting only a part of the file.

  • The Content-Range header indicates which portion of the file is being sent.

How We Handle Range in Node.js

In the streaming server, we use: 

javascript
const range = req.headers.range;
if (!range) {
    return res.status(400).send("Requires Range header");
}

  • If the client doesn’t send a Range header, we reject the request because streaming requires it.

Then, we extract the byte range: 

javascript
const start = Number(range.replace(/\D/g, "")); // Extracts the starting byte
const end = Math.min(start + CHUNK_SIZE, videoSize - 1);

  • This allows us to stream only the requested chunk of the video.

Without the Range Header?

If you remove it, the entire video would be sent at once: 

javascript
fs.createReadStream(videoPath).pipe(res);

  • This wastes bandwidth and makes seeking slow, as the browser has to download the whole file before skipping.

In Short:

The Range header makes progressive video streaming possible by letting the client request only small chunks of a video file instead of downloading everything at once.

Why do videoSize - 1?

Good question! The reason we do videoSize - 1 instead of just videoSize is because byte ranges in HTTP are zero-based. Let's break this down:

1️⃣ Byte Indexing in HTTP

  • In computing, byte positions start from 0.

  • If a video file has videoSize = 5000000 bytes, the last byte is at position 4999999, not 5000000.

🔹 Example: 

Video file size: 5,000,000 bytes
First byte position: 0
Last byte position: 4,999,999 (videoSize - 1)

So, when we calculate the end byte, we make sure it doesn’t exceed the valid range.

2️⃣ Preventing Out-of-Bounds Reads 

javascript
const end = Math.min(start + CHUNK_SIZE, videoSize - 1);

  • If videoSize is 5,000,000, but we set end = 5000000, we'd be requesting a byte that doesn’t exist.

  • Using videoSize - 1 ensures we don’t go out of bounds when reading the file.

3️⃣ Example with a Real Request

Imagine a client requests: 

http
Range: bytes=4000000-

And our file size is 5,000,000 bytes.

🔹 Without videoSize - 1: 

javascript
end = Math.min(4000000 + 1000000, 5000000);
end = 5000000 ❌ (out of range!)

🔹 With videoSize - 1: 

javascript
end = Math.min(4000000 + 1000000, 4999999);
end = 4999999 ✅ (correct)

💡 Final Answer

We use videoSize - 1 to ensure: ✅ Byte positions stay within valid range (0 to videoSize - 1).
✅ No out-of-bounds errors when reading the file.

How to transform video demand based on user's internet speed?

To adjust video quality dynamically based on the user's internet speed, you need to implement adaptive bitrate streaming (ABR). This allows the server to deliver different video resolutions (e.g., 240p, 480p, 720p, 1080p) depending on the user's bandwidth. Here’s how to do it in Node.js:

1️⃣ Choose an Adaptive Streaming Format

You need a streaming format that supports multiple video qualities:

  • HLS (HTTP Live Streaming) → Best for web & mobile (used by YouTube, Netflix, etc.).

  • DASH (Dynamic Adaptive Streaming over HTTP) → Alternative to HLS, used by YouTube.

For simplicity, let’s go with HLS.

2️⃣ Convert Video to Multiple Resolutions

Use FFmpeg to create multiple versions of the video. 

bash
ffmpeg -i input.mp4 \
  -vf "scale=640:360" -c:v libx264 -b:v 800k -hls_segment_filename 360p_%03d.ts 360p.m3u8 \
  -vf "scale=1280:720" -c:v libx264 -b:v 2500k -hls_segment_filename 720p_%03d.ts 720p.m3u8 \
  -vf "scale=1920:1080" -c:v libx264 -b:v 5000k -hls_segment_filename 1080p_%03d.ts 1080p.m3u8

This generates:

  • 360p.m3u8 (playlist for 360p)

  • 720p.m3u8 (playlist for 720p)

  • 1080p.m3u8 (playlist for 1080p)

  • .ts files (video chunks)

3️⃣ Create a Master Playlist

A master .m3u8 file tells the video player which qualities are available.

Create master.m3u8: 

m3u8
#EXTM3U
#EXT-X-STREAM-INF:BANDWIDTH=800000,RESOLUTION=640x360
360p.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=2500000,RESOLUTION=1280x720
720p.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=5000000,RESOLUTION=1920x1080
1080p.m3u8

4️⃣ Serve the Video in Node.js

Now, set up a Node.js Express server to serve the .m3u8 files. 

javascript

const path = require("path");

const app = express();
app.use(express.static("videos")); // Serve HLS files

  res.sendFile(path.join(__dirname, "videos", "master.m3u8"));

app.listen(3000, () => console.log("Streaming server running on port 3000"));

5️⃣ Play the Video in a Web Browser

Use HLS.js (for browsers that don’t support HLS natively):

6️⃣ How Does It Adapt?

  • The video player monitors the user's internet speed.

  • If the connection is slow, it automatically switches to a lower resolution.

  • If the connection improves, it upgrades to a higher resolution.

How does the video player monitor it? Is it done internally by the video tag in html?

Great question! The HTML5 <video> tag itself does not handle adaptive streaming. Instead, the video player (e.g., HLS.js, DASH.js, or native HLS in Safari) manages it internally using these mechanisms:

1️⃣ How Does the Player Detect Network Speed?

Most modern video players use buffering and download speed monitoring to decide which resolution to play. Here’s how:

🔹 Method 1: Segment Load Time (Used by HLS/DASH)

  • Videos are broken into small segments (e.g., 4-10 seconds each).

  • The player measures how fast it downloads a segment.

  • If a segment downloads too slowly, it switches to a lower resolution.

  • If a segment downloads quickly, it switches to a higher resolution.

Example:

  • Fast internet: 4K video loads quickly → player keeps high resolution.

  • Slow internet: 4K segment loads too slowly → player switches to 1080p or lower.

🔹 Method 2: Buffer Monitoring (Avoiding Buffering)

  • The player tracks the buffer size (how much video is preloaded).

  • If the buffer starts running low, it reduces the quality.

  • If the buffer stays full, it increases the quality.

Example:

  • Watching a video on WiFi → smooth streaming at 1080p.

  • Moving to 4G → buffering detected → player drops to 720p.

2️⃣ Does the <video> Tag Handle It?

No, the <video> tag alone does not handle adaptive streaming.
However, some browsers (Safari, iOS) support HLS natively, meaning the built-in player does handle adaptive streaming.

For other browsers (Chrome, Firefox, Edge), you need a JavaScript player like:

  • HLS.js (for .m3u8 HLS streaming)

  • DASH.js (for MPEG-DASH streaming)

3️⃣ Example: HLS.js Automatically Adjusting Quality

If you're using HLS.js, it automatically monitors bandwidth and switches resolutions.

  }
</script>

1️⃣ Measure Internet Speed Manually

  3. Calculating speed using:

    Speed (Mbps)=File Size (bits)Download Time (seconds)×106\text{Speed (Mbps)} = \frac{\text{File Size (bits)}}{\text{Download Time (seconds)} \times 10^6}Speed (Mbps)=Download Time (seconds)×106File Size (bits)​

  4. Switching video quality based on speed.

2️⃣ Implementing the Speed Test in JavaScript

Here’s a simple way to measure download speed using JavaScript: 

javascript
function measureSpeed(callback) {
    const fileUrl = "/test-file.mp4"; // Small test file (~1MB)
    const startTime = Date.now();

    fetch(fileUrl).then(response => response.blob()).then(blob => {
        const endTime = Date.now();
        const duration = (endTime - startTime) / 1000; // Convert ms to seconds
        const fileSize = blob.size * 8; // Convert bytes to bits

        const speedMbps = fileSize / (duration * 1_000_000); // Convert bits to Mbps
        callback(speedMbps);
    });
}

// Example usage
measureSpeed(speed => {
    console.log(`Your internet speed: ${speed.toFixed(2)} Mbps`);
});

🔹 Explanation:

  • Fetches a small test file (/test-file.mp4).

  • Measures start & end time to calculate download duration.

  • Converts file size (bytes → bits) and calculates speed in Mbps.

  • Calls callback(speedMbps) with the result.

Can't I transform each chunk of fs.createReadStream in node.js?

Yes! You can dynamically transform each chunk of a fs.createReadStream in Node.js before sending it to the client. This allows you to adjust the video quality on the fly based on the user's internet speed.

1️⃣ How Does It Work?

Instead of switching entire video files, we can:

  1. Read video chunks using fs.createReadStream().

  2. Transform each chunk (e.g., compress, re-encode, resize bitrate).

  3. Stream the transformed chunk to the client.

2️⃣ Basic Example: Streaming Video with fs.createReadStream

Here’s how a basic streaming server works: 

javascript
const fs = require("fs");
const http = require("http");

http.createServer((req, res) => {
    const filePath = "video.mp4"; // Original video
    const stat = fs.statSync(filePath);
    const fileSize = stat.size;

    // Get the range header (if requested)
    const range = req.headers.range;
    if (!range) {
        res.writeHead(416, { "Content-Range": `bytes */${fileSize}` });
        return res.end();
    }

    const CHUNK_SIZE = 10 ** 6; // 1MB chunks
    const start = Number(range.replace(/\D/g, ""));
    const end = Math.min(start + CHUNK_SIZE, fileSize - 1);

    // Set response headers
    res.writeHead(206, {
        "Content-Range": `bytes ${start}-${end}/${fileSize}`,
        "Accept-Ranges": "bytes",
        "Content-Length": end - start + 1,
        "Content-Type": "video/mp4",
    });

    // Stream the chunk
    const stream = fs.createReadStream(filePath, { start, end });
    stream.pipe(res);
}).listen(3000, () => console.log("Server running on http://localhost:3000"));

🔹 How It Works:

  • Reads chunks of 1MB (CHUNK_SIZE).

  • Uses range headers for partial streaming.

  • Streams the video directly to the browser.

3️⃣ Transform Each Chunk (Compression or Resizing)

If you want to modify each chunk before sending it, use Node.js streams and FFmpeg.

🔹 Example: Compress Video Chunks on the Fly 

javascript
const { spawn } = require("child_process");
const fs = require("fs");
const http = require("http");

http.createServer((req, res) => {
    const filePath = "video.mp4";
    const stat = fs.statSync(filePath);
    const fileSize = stat.size;
    
    const range = req.headers.range;
    if (!range) {
        res.writeHead(416, { "Content-Range": `bytes */${fileSize}` });
        return res.end();
    }

    const CHUNK_SIZE = 10 ** 6; // 1MB
    const start = Number(range.replace(/\D/g, ""));
    const end = Math.min(start + CHUNK_SIZE, fileSize - 1);

    res.writeHead(206, {
        "Content-Range": `bytes ${start}-${end}/${fileSize}`,
        "Accept-Ranges": "bytes",
        "Content-Length": end - start + 1,
        "Content-Type": "video/mp4",
    });

    // Read the video chunk
    const videoStream = fs.createReadStream(filePath, { start, end });

    // Use FFmpeg to compress each chunk
    const ffmpegProcess = spawn("ffmpeg", [
        "-i", "pipe:0",       // Read from stdin
        "-b:v", "500k",       // Reduce bitrate (adjustable)
        "-f", "mp4",          // Output format
        "pipe:1"              // Write to stdout
    ]);

    videoStream.pipe(ffmpegProcess.stdin); // Send the chunk to FFmpeg
    ffmpegProcess.stdout.pipe(res);        // Send transformed chunk to client
}).listen(3000, () => console.log("Server running on http://localhost:3000"));

🔹 What’s Happening Here?

  • The server reads only the requested chunk (fs.createReadStream).

  • The chunk is piped into FFmpeg, which compresses/transcodes it.

  • The transformed chunk is streamed directly to the client.

        const start = Number(range.replace(/\D/g, ""));
        const end = Math.min(start + CHUNK_SIZE, fileSize - 1);

        res.writeHead(206, {
            "Content-Range": `bytes ${start}-${end}/${fileSize}`,
            "Accept-Ranges": "bytes",
            "Content-Length": end - start + 1,
            "Content-Type": "video/mp4",
        });

        const videoStream = fs.createReadStream(filePath, { start, end });

        // Adjust bitrate dynamically
        const ffmpegProcess = spawn("ffmpeg", [
            "-i", "pipe:0",
            "-b:v", bitrate, // Dynamically selected
            "-f", "mp4",
            "pipe:1"
        ]);

        videoStream.pipe(ffmpegProcess.stdin);
        ffmpegProcess.stdout.pipe(res);
    });
}).listen(3000, () => console.log("Adaptive streaming server running!"));

🔹 How This Works

  • Uses measureSpeed(speed => { ... }) to detect network speed.

  • Chooses bitrate dynamically (500k, 1000k, 2000k).

  • Streams video chunks with optimized bitrate for each user.

5️⃣ Alternative: HLS with Dynamic Bitrate

Instead of modifying each chunk manually, another approach is:

  1. Pre-encode multiple quality levels (1080p, 720p, 480p).

  2. Use an .m3u8 HLS playlist to let the player switch dynamically.

This is easier and more efficient than on-the-fly transformation.
