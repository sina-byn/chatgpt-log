Download file in Node.js

how to download a file in node js

You can easily download a file in Node.js using built-in modules like https, http, or external libraries like axios or node-fetch.

Here are two clear examples using native modules and Axios:

✅ Using Built-in Modules (https / fs): 

javascript
const https = require('https');
const fs = require('fs');

const url = 'https://example.com/file.zip';
const filePath = 'file.zip';

const file = fs.createWriteStream(filePath);

https.get(url, (response) => {
  if (response.statusCode !== 200) {
    console.error(`Download failed. Status Code: ${response.statusCode}`);
    return;
  }

  response.pipe(file);

  file.on('finish', () => {
    file.close();
    console.log('Download completed.');
  });

}).on('error', (err) => {
  fs.unlink(filePath, () => {}); // Delete incomplete file
  console.error(`Error: ${err.message}`);
});

✅ Using Axios (Recommended for simplicity):

First, install Axios: 

bash
npm install axios

Then use the following code: 

javascript
const axios = require('axios');
const fs = require('fs');

const url = 'https://example.com/file.zip';
const filePath = 'file.zip';

async function downloadFile(url, path) {
  const response = await axios({
    method: 'GET',
    url: url,
    responseType: 'stream'
  });

  const writer = fs.createWriteStream(path);

  response.data.pipe(writer);

  return new Promise((resolve, reject) => {
    writer.on('finish', () => {
      console.log('Download completed.');
      resolve();
    });

    writer.on('error', (err) => {
      fs.unlink(path, () => {});
      console.error(`Error: ${err.message}`);
      reject(err);
    });
  });
}

downloadFile(url, filePath);

📌 Summary of Steps:

  1. Choose between built-in modules (https) or libraries (axios).

  2. Use a stream (fs.createWriteStream) to write the file.

  3. Handle success/error events properly.

This ensures efficient, robust downloading of files in Node.js.

how to download it within a range

To download a file within a specific byte range in Node.js, you can set the HTTP header Range. This is commonly used for downloading large files in segments or resuming interrupted downloads.

Here's how you can achieve this easily:

🚀 Using Built-in Modules (https) 

javascript
const https = require('https');
const fs = require('fs');

const url = 'https://example.com/file.zip';
const filePath = 'partial-file.zip';

// Define the byte range (for example, first 1MB of file)
const startByte = 0;
const endByte = 1048575; // 1 MB = 1024 * 1024 - 1

const options = {
  headers: {
    'Range': `bytes=${startByte}-${endByte}`
  }
};

https.get(url, options, (res) => {
  if (res.statusCode !== 206) { // 206 Partial Content
    console.error(`Unexpected status code: ${res.statusCode}`);
    res.resume(); // Consume response data to free up memory
    return;
  }

  const fileStream = fs.createWriteStream(filePath);

  res.pipe(fileStream);

  fileStream.on('finish', () => {
    fileStream.close();
    console.log('Partial download completed.');
  });

}).on('error', (err) => {
  fs.unlink(filePath, () => {});
  console.error(`Download failed: ${err.message}`);
});

🚀 Using Axios 

javascript
const axios = require('axios');
const fs = require('fs');

const url = 'https://example.com/file.zip';
const filePath = 'partial-file.zip';

// Byte range (e.g., bytes 0 to 1MB-1)
const startByte = 0;
const endByte = 1048575;

async function downloadRange(url, path, start, end) {
  const response = await axios.get(url, {
    headers: {
      'Range': `bytes=${start}-${end}`
    },
    responseType: 'stream'
  });

  if (response.status !== 206) {
    throw new Error(`Unexpected status code: ${response.status}`);
  }

  const writer = fs.createWriteStream(path);
  response.data.pipe(writer);

  return new Promise((resolve, reject) => {
    writer.on('finish', () => {
      console.log('Partial download completed.');
      resolve();
    });
    writer.on('error', (err) => {
      fs.unlink(path, () => {});
      console.error(`Error: ${err.message}`);
      reject(err);
    });
  });
}

downloadRange(url, filePath, startByte, endByte);

📌 Important Notes:

  • When requesting byte ranges, the server must support HTTP Range Requests (most servers do).

  • If the range request succeeds, you'll get an HTTP status code 206 Partial Content.

  • Adjust startByte and endByte values as per your requirements.

  • Useful for segmented downloads, resuming downloads, or parallel downloading.

That's how you can download a specific range of bytes from a file in Node.js!

download 8 threads at the same time

To download a file in 8 parallel threads (segments) using Node.js, you can:

  1. Get the file size.

  2. Split it into 8 ranges.

  3. Download each range concurrently using HTTP Range header.

  4. Merge the parts into one file.

Here’s a complete working example using axios, fs, and Promise.all:

✅ Step-by-Step Code

Install required package first: 

bash
npm install axios

Then use this code: 

javascript
const fs = require('fs');
const axios = require('axios');
const path = require('path');
const os = require('os');

const FILE_URL = 'https://example.com/largefile.zip';
const OUTPUT_FILE = 'final.zip';
const THREADS = 8;

async function getFileSize(url) {
  const res = await axios.head(url);
  const size = parseInt(res.headers['content-length'], 10);
  if (isNaN(size)) throw new Error('Could not get file size');
  return size;
}

async function downloadPart(url, start, end, index) {
  const response = await axios.get(url, {
    headers: { Range: `bytes=${start}-${end}` },
    responseType: 'stream'
  });

  const tempPath = path.join(os.tmpdir(), `part-${index}`);
  const writer = fs.createWriteStream(tempPath);

  response.data.pipe(writer);

  return new Promise((resolve, reject) => {
    writer.on('finish', () => resolve(tempPath));
    writer.on('error', reject);
  });
}

async function mergeParts(tempPaths, outputPath) {
  const writer = fs.createWriteStream(outputPath);

  for (const tempPath of tempPaths) {
    const data = fs.readFileSync(tempPath);
    writer.write(data);
    fs.unlinkSync(tempPath); // delete part after merge
  }

  writer.end();
  console.log('Merge completed:', outputPath);
}

(async () => {
  const size = await getFileSize(FILE_URL);
  const partSize = Math.ceil(size / THREADS);
  const downloadPromises = [];

  for (let i = 0; i < THREADS; i++) {
    const start = i * partSize;
    const end = i === THREADS - 1 ? size - 1 : (start + partSize - 1);
    downloadPromises.push(downloadPart(FILE_URL, start, end, i));
  }

  const tempPaths = await Promise.all(downloadPromises);
  await mergeParts(tempPaths, OUTPUT_FILE);
})();

⚙️ What This Does:

  • Detects the total file size.

  • Splits the download into 8 byte ranges.

  • Downloads each part concurrently.

  • Merges them in order into a final file.

  • Deletes temporary part files.

⚠️ Notes:

  • Works only if the server supports HTTP range requests (status 206).

  • Use os.tmpdir() or any other temp path to store parts safely.

  • Optional: Add retry/failure handling for robustness.

add resume and pause functionality if supported by the server

Adding pause/resume functionality to a multi-threaded downloader in Node.js is possible if the server supports Range requests, and if you track the downloaded byte ranges.

Here’s how to do it:

✅ Strategy for Pause/Resume in Multi-threaded Downloader

🧠 Core Concepts:

  • Each thread writes to a temp file, and we track the bytes downloaded per thread.

  • We use a progress.json file to save state (start, end, downloaded).

  • On resume, we read this file and continue unfinished ranges.

🛠 Updated Code with Pause/Resume Support 

javascript
const fs = require('fs');
const axios = require('axios');
const path = require('path');
const os = require('os');

const FILE_URL = 'https://example.com/largefile.zip';
const OUTPUT_FILE = 'final.zip';
const THREADS = 8;
const PROGRESS_FILE = 'progress.json';

async function getFileSize(url) {
  const res = await axios.head(url);
  const size = parseInt(res.headers['content-length'], 10);
  if (isNaN(size)) throw new Error('Could not get file size');
  return size;
}

function saveProgress(progress) {
  fs.writeFileSync(PROGRESS_FILE, JSON.stringify(progress, null, 2));
}

function loadProgress() {
  if (fs.existsSync(PROGRESS_FILE)) {
    return JSON.parse(fs.readFileSync(PROGRESS_FILE));
  }
  return null;
}

async function downloadPart(url, part, index) {
  const tempPath = path.join(os.tmpdir(), `part-${index}`);
  const writer = fs.createWriteStream(tempPath, { flags: 'a' }); // append if resuming

  const headers = {
    Range: `bytes=${part.downloaded}-${part.end}`
  };

  const response = await axios.get(url, {
    headers,
    responseType: 'stream'
  });

  return new Promise((resolve, reject) => {
    response.data.on('data', chunk => {
      fs.appendFileSync(tempPath, chunk);
      part.downloaded += chunk.length;
      saveProgress(progress); // update progress on each chunk
    });

    response.data.on('end', () => resolve(tempPath));
    response.data.on('error', reject);
  });
}

async function mergeParts(progress, outputPath) {
  const writer = fs.createWriteStream(outputPath);

  for (let i = 0; i < progress.length; i++) {
    const tempPath = path.join(os.tmpdir(), `part-${i}`);
    const data = fs.readFileSync(tempPath);
    writer.write(data);
    fs.unlinkSync(tempPath);
  }

  fs.unlinkSync(PROGRESS_FILE);
  writer.end();
  console.log('Download complete:', outputPath);
}

let progress;

(async () => {
  const size = await getFileSize(FILE_URL);
  const partSize = Math.ceil(size / THREADS);

  progress = loadProgress();
  if (!progress) {
    // initialize progress if not resuming
    progress = Array.from({ length: THREADS }).map((_, i) => {
      const start = i * partSize;
      const end = i === THREADS - 1 ? size - 1 : start + partSize - 1;
      return { start, end, downloaded: start };
    });
    saveProgress(progress);
  }

  const downloadPromises = progress.map((part, i) => {
    if (part.downloaded > part.end) return Promise.resolve(); // already complete
    return downloadPart(FILE_URL, part, i);
  });

  await Promise.all(downloadPromises);
  await mergeParts(progress, OUTPUT_FILE);
})();

  • 🟢 Pause = Just stop the script (e.g. CTRL+C).

  • 🟢 Resume = Run the script again, it continues where it left off.

  • 🟢 Each thread stores partial data + tracked progress.

  • 🟢 Automatically skips finished parts.

check if the server supports streaming by http headers

To check if a server supports streaming and range requests, you can examine its HTTP response headers — especially:

  • Accept-Ranges → indicates support for byte-range requests.

  • Content-Length → needed for resuming logic.

  • Transfer-Encoding: chunked → suggests streaming (chunked transfer).

  • Content-Type → helps infer if the content is streamable (e.g., video/audio).

✅ Example: Check Server Streaming Support with Axios 

javascript
const axios = require('axios');

const url = 'https://example.com/largefile.zip';

async function checkStreamingSupport(url) {
  try {
    const res = await axios.head(url);

    const acceptRanges = res.headers['accept-ranges'];
    const contentLength = res.headers['content-length'];
    const transferEncoding = res.headers['transfer-encoding'];
    const contentType = res.headers['content-type'];

    console.log('--- Server Headers ---');
    console.log('Accept-Ranges:', acceptRanges);
    console.log('Content-Length:', contentLength);
    console.log('Transfer-Encoding:', transferEncoding);
    console.log('Content-Type:', contentType);

    if (acceptRanges === 'bytes') {
      console.log('✅ Server supports partial content (Range requests).');
    } else {
      console.log('❌ Server does NOT support Range requests.');
    }

    if (transferEncoding === 'chunked') {
      console.log('✅ Server supports streaming via chunked transfer.');
    } else if (contentLength) {
      console.log('✅ Server provides Content-Length (can download in parts).');
    } else {
      console.log('❌ No clear support for streaming or partial download.');
    }

  } catch (err) {
    console.error('Error checking server:', err.message);
  }
}

🧠 How Speed Tracking Works:

  • On every data chunk, we:

    • Track the number of bytes received.

    • Calculate speed over time.

  • Use setInterval to update the displayed speed every second.

🛠 UPDATED CODE SNIPPET

Replace the downloadPart() function in the previous code with this version: 

javascript
async function downloadPart(url, part, index, bar) {
  const tempPath = path.join(os.tmpdir(), `part-${index}`);
  const writer = fs.createWriteStream(tempPath, { flags: 'a' });

  const download = async (attempt = 1) => {
    try {
      const headers = { Range: `bytes=${part.downloaded}-${part.end}` };
      const response = await axios.get(url, {
        headers,
        responseType: 'stream',
      });

      let received = 0;
      let lastUpdateTime = Date.now();
      let speed = 0;

      // Speed updater
      const speedInterval = setInterval(() => {
        const now = Date.now();
        const elapsed = (now - lastUpdateTime) / 1000; // in seconds
        speed = received / elapsed; // bytes/sec
        bar.update(part.downloaded - part.start, {
          speed: formatSpeed(speed),
        });
        received = 0;
        lastUpdateTime = now;
      }, 1000);

      return new Promise((resolve, reject) => {
        response.data.on('data', (chunk) => {
          writer.write(chunk);
          part.downloaded += chunk.length;
          received += chunk.length;
        });

        response.data.on('end', () => {
          clearInterval(speedInterval);
          bar.update(part.end - part.start, {
            speed: 'Done',
          });
          resolve(tempPath);
        });

        response.data.on('error', (err) => {
          clearInterval(speedInterval);
          reject(err);
        });
      });
    } catch (err) {
      if (attempt < MAX_RETRIES) {
        console.warn(`🔁 Retry [${index}] (attempt ${attempt})`);
        return download(attempt + 1);
      } else {
        throw new Error(`❌ Failed to download part ${index}: ${err.message}`);
      }
    }
  };

  return download();

Absolutely! Let's break down the throttling logic step by step so it's easy to understand and customize.

🧠 Goal of Throttling

Throttle = "slow down" the download speed.

We’re controlling:

  • ✅ Per-thread speed (each thread shouldn't exceed a certain speed)

  • ✅ Global speed (all threads combined shouldn’t go above a limit)

This helps:

  • Prevent network overload

  • Stay within API rate limits

  • Avoid consuming all available bandwidth

🔄 How It Works – Conceptually

1. Per-Thread Throttling

Purpose: Make each thread obey a max speed (e.g., 1MB/s).

Logic:

  • After writing a chunk, calculate: 

    delay = chunkSize / threadLimitPerSecond

  • Example:

    • Chunk = 100KB

    • Limit = 1MB/s = 1024KB/s

    • Delay = 100 / 1024 = 0.0976 seconds (~97ms)

  • We wait that long using await sleep().

Code:

js
const delayPerChunk = (chunk.length / THREAD_SPEED_LIMIT) * 1000;
if (delayPerChunk > 5) await sleep(delayPerChunk); // skip tiny delays

2. Global Speed Throttling

Purpose: All threads combined must not exceed total bandwidth (e.g., 5MB/s).

Logic:

  • Use a "token bucket" (shared value globalBucket)

  • Each second, refill it to the allowed global bandwidth.

  • Before writing a chunk:

    • Check if there are enough "tokens" (bytes) left in globalBucket.

    • If yes → proceed and subtract the bytes.

    • If no → wait and retry.

Code: 

js
// refill every second
setInterval(() => {
  globalBucket = GLOBAL_SPEED_LIMIT;
}, 1000);

// in download:
while (globalBucket < chunk.length) {
  await sleep(10); // wait a bit
}
globalBucket -= chunk.length;

Throttle Type Controls Use Case
Per-thread Fairness per task Don’t let one thread hog speed
Global Total bandwidth Don't exceed total network cap

This two-layer system gives you fine-grained control over download behavior.

how does using delays is the same as restricting network bandwidth usage?

Great question — and you're absolutely right to dig deeper. Let’s clarify:

✅ Short Answer

Delays don't restrict actual network bandwidth at the TCP level.
Instead, they control how fast your app reads and writes data, which indirectly limits how much data flows through.

So:

⏱ Delaying read/write operations ≠ true bandwidth shaping,
but ✅ it limits your effective bandwidth usage from the app side.

🧠 Here's What Actually Happens

🎯 Your Node.js app is pulling data from a stream (e.g., HTTP response):

  • The OS/network stack buffers incoming data.

  • Your code decides when to read it.

  • If you pause reading (via await sleep()), the TCP window shrinks, and the server eventually slows down sending.

Effect: You "throttle" how fast you pull data → server adapts → traffic slows down.

📉 Example:

Let’s say:

  • You delay 100ms after reading each 100KB

  • That’s ~1MB/s effective pull rate.

Even though:

  • The server could send at 20MB/s

  • You’re voluntarily reading at just 1MB/s

➡️ So the total bandwidth used stays low, though the physical NIC is still capable of more.

⚙️ Analogy

Imagine a high-speed water tap and a small cup:

  • The tap is fast (server can send a lot).

  • You fill the cup, wait a bit, then drink.

  • You’re not limiting the tap — just how fast you take sips.

❌ What It’s Not

  • It’s not real QoS (Quality of Service).

  • It doesn’t prevent other apps from using the bandwidth.

  • It can’t cap traffic outside your app.

✅ But It Works Well When…

  • You’re writing a CLI downloader or API scraper.

  • You need basic control to avoid server bans.

  • You’re working on multiple concurrent requests and want fairness.

🔧 If You Need True Bandwidth Control...

Then consider using lower-level tools:

Tool/Method Description
tc (Linux Traffic Control) Kernel-level bandwidth control
trickle User-level bandwidth limiter wrapper
Docker network config Limit containers
Proxy with shaping (e.g., Squid) Centralized control

✅ TL;DR

Method Controls Network? App-Level Control OS-Level Bandwidth Cap
await sleep() after chunk ❌ (not true throttle) ✅ Yes ❌ No
tc, trickle ✅ Yes ❌ External ✅ Yes

So — you're not forcing the network to slow down,
but you’re slowing your own usage, which results in the same outcome from the server’s perspective.
