Hash-Based Sharding Guide

In hash-based sharding how to shard databases?

Hash-based sharding is a technique used to distribute data across multiple databases (or database partitions) using a hash function. Here's a clear explanation of how to shard databases using this method:

🔹 What Is Hash-Based Sharding?

In hash-based sharding, the shard key (a specific field in your data, like user_id, customer_id, or email) is passed through a hash function, and the output is used to determine which shard the data belongs to.

🔹 Steps to Shard a Database Using Hash-Based Sharding

1. Choose a Shard Key

Pick a field that:

  • Has high cardinality (many distinct values).

  • Is used frequently in queries.

Example: user_id for a user database.

2. Define the Hash Function

Use a consistent hash function (e.g., MD5, SHA-256, MurmurHash, or even a simple modulus operation) to convert the shard key into a number.

Example: hash(user_id) % N, where N is the number of shards.

3. Assign Shards

Map the hash output to shards. If using modulus:

  • shard_number = hash(user_id) % 4 → 4 shards (shard_0 to shard_3)

4. Route Data to the Right Shard

Based on the hash result, route incoming writes or queries to the appropriate database.

Example:

python
def get_shard(user_id, num_shards):
    shard_index = hash(user_id) % num_shards
    return f"shard_{shard_index}"

5. Store Data in Corresponding Shard

Each shard is a separate database (or a table within a database), and you store or query the data only from that shard.

🔹 Pros and Cons

✅ Pros:

  • Even distribution of data (if hash function and shard key are chosen well).

  • Simple and deterministic routing.

❌ Cons:

  • Harder to perform range queries (e.g., user_id > 1000).

  • Rebalancing is complex if you need to add/remove shards (you may need consistent hashing to reduce data movement).

🔹 Example

Assume:

  • user_id = 12345

  • 4 shards: shard_0 to shard_3 

python
shard = hash(12345) % 4  # Result might be 1

→ Store user_id = 12345 in shard_1

how about md5?

Using MD5 for hash-based sharding is a common and effective approach when you need a uniform distribution of data. Here's how you can use MD5 in hash-based sharding:

🔹 How to Use MD5 for Hash-Based Sharding

1. Choose a Shard Key

Let’s say the shard key is user_id = 12345.

2. Generate MD5 Hash

Hash the shard key using MD5 and get a hexadecimal string. 

python
import hashlib

def md5_hash_shard(key, num_shards):
    md5_hash = hashlib.md5(str(key).encode()).hexdigest()
    hash_int = int(md5_hash, 16)  # Convert hex to integer
    shard_index = hash_int % num_shards
    return f"shard_{shard_index}"

3. Determine the Shard

Assuming 4 shards (shard_0 to shard_3): 

python
shard = md5_hash_shard(12345, 4)
print(shard)  # e.g., "shard_2"

🔹 Why Use MD5?

✅ Advantages:

  • Good distribution across shards (due to uniformity of MD5).

  • Works well even when the key values are sequential or patterned.

⚠️ Considerations:

  • MD5 is fast, but not cryptographically secure — that’s fine for sharding.

  • Adding or removing shards requires remapping most data (unless you use consistent hashing).

🔹 Optional: Use First Few Bytes Only

For performance (less math), you can use the first few bytes of the MD5 hash: 

python
def md5_prefix_shard(key, num_shards):
    md5_hash = hashlib.md5(str(key).encode()).hexdigest()
    short_hash = md5_hash[:8]  # Use first 4 bytes (8 hex chars)
    hash_int = int(short_hash, 16)
    return f"shard_{hash_int % num_shards}"

This is still sufficiently distributed for most use cases.

✅ Summary

Step Action
1 Choose a good shard key
2 Hash it with MD5
3 Convert hash to integer
4 Compute hash_int % num_shards
5 Route data to that shard

what is uniformity of md5?

Great question. When we talk about the uniformity of MD5, we're referring to how evenly the hash values are distributed across the entire output space. This matters a lot for sharding, because you want each shard to receive roughly the same number of keys (i.e., balanced load).

🔹 What Is Uniformity?

Uniformity means that every possible hash output is equally likely (in theory), and similar inputs produce very different and unpredictable outputs.

For MD5:

  • Output: 128-bit (32-character hexadecimal string).

  • Output space: 21282^{128}2128 possible values.

  • Uniformity: If MD5 is applied to a large, diverse set of keys (e.g., user_id, email), the outputs will be evenly spread across the hash space.

🔹 Why MD5 Is Considered Uniform

  • Avalanche effect: A small change in input leads to a drastically different hash.

  • Empirically uniform: Despite being broken cryptographically, MD5 still distributes hashes evenly in most non-security applications.

  • Statistical balance: Over a large input set, each bit of the output has ~50% chance of being 0 or 1.

🔹 Uniformity in Sharding

Suppose you use: 

python
shard_index = int(md5(user_id)) % 4

If MD5 is uniform, then over millions of user_ids:

  • About 25% will map to shard 0

  • About 25% to shard 1

  • ...and so on

This avoids hotspots (some shards getting more data than others).

🔹 Visual Example

101 c1b4... 0 0
102 81dc... 2 2
103 6c0f... 3 3

Even though the user_ids are close together, MD5 hashes them into well-separated values — that's uniformity in action.

✅ Summary

  • MD5 has good statistical uniformity, making it suitable for sharding.

  • It ensures even distribution across shards.

  • It’s deterministic, so the same key always maps to the same shard.

in md5 similar input produces a different output?

Yes — in MD5, even very similar inputs produce drastically different outputs. This property is called the avalanche effect.

🔹 What Is the Avalanche Effect?

The avalanche effect is a desired property of cryptographic hash functions like MD5, where a small change in input (even one bit) causes a completely different output.

🔹 Example: MD5 Hashes of Similar Inputs

Let’s compare the MD5 hashes of two similar strings:

🔸 Input 1: "user123" 

python
MD5("user123") = 6adf97f83acf6453d4a6a4b1070f3754

🔸 Input 2: "user124" (only last character changed) 

python
MD5("user124") = 04d06b956c63b2cdd4c2e5b3edb3d620

✅ These two inputs differ by only one character, yet their hashes are completely different — this demonstrates the avalanche effect.

🔹 Why This Matters for Sharding

This property helps distribute data uniformly:

  • Without avalanche: similar keys (e.g., user123, user124, user125) might hash to the same or neighboring shards → hotspot risk.

  • With avalanche (as in MD5): those keys hash to very different values, which spread evenly across shards.

🔹 Summary

Property MD5 Supports
Deterministic ✅ Yes
Small input change → big hash change ✅ Yes (avalanche effect)
Uniform distribution ✅ Yes (statistically)
Cryptographic security ❌ No (deprecated for security)

So yes — similar input does produce very different output in MD5. That’s one reason it’s still useful in sharding and data partitioning, even though it’s insecure for cryptographic purposes.
