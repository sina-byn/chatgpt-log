E2EE in Chat Apps

how does e2e encryption work in chat apps?

End-to-end encryption (E2EE) in chat apps ensures that only the communicating users (the sender and the recipient) can read the messages. Even the service provider (like WhatsApp, Signal, or Telegram) cannot access the content of the messages. Here’s how it works:

🔐 Basic Concept

At the heart of E2EE is public-key cryptography:

  • Each user has:

    • A public key (shared with others)

    • A private key (kept secret)

When Alice wants to send a message to Bob:

  1. Alice encrypts the message using Bob’s public key.

  2. Only Bob’s private key can decrypt it.

  3. Even if someone (like the server or a hacker) intercepts the encrypted message, they cannot read it without Bob’s private key.

🧩 Key Components

1. Key Exchange

  • Secure key exchange protocols (like X3DH in Signal) are used to share encryption keys safely, even over an insecure network.

  • This often uses Diffie-Hellman or Elliptic Curve Cryptography (ECC).

2. Session Keys

  • For performance, chat apps usually create temporary symmetric session keys using the initial key exchange.

  • Messages are encrypted with fast symmetric encryption (like AES), and the symmetric key is secured with the public/private key system.

3. Forward Secrecy

  • Every message or session uses a new key, so if one key is compromised, previous messages remain secure.

  • Signal Protocol implements this with its "Double Ratchet" algorithm.

4. Authentication

  • Apps verify the identity of users (e.g., by verifying fingerprints or QR codes).

  • This prevents man-in-the-middle (MITM) attacks.

🛡️ Example: Signal Protocol (used by WhatsApp, Signal, Messenger)

  • Initial Key Exchange: Using X3DH, devices establish a shared secret.

  • Message Encryption: Messages are encrypted with evolving keys via the Double Ratchet.

  • Integrity: Encrypted messages are signed and verified to ensure they weren’t tampered with.

🧠 Summary

  • 🔒 Only sender and recipient can read the messages.

  • 🏢 Not even the app provider can decrypt the content.

  • 🔁 Regularly changing keys ensures past/future messages stay safe even if one key is leaked.

Sure! Let's go deep into how WhatsApp’s end-to-end encryption protocol works. WhatsApp uses the Signal Protocol, developed by Open Whisper Systems, with some adaptations. Here's a breakdown of the key components:

📲 WhatsApp’s E2E Encryption Protocol – Deep Dive

1. Core Components

WhatsApp uses:

  • X3DH (Extended Triple Diffie-Hellman) for initial key agreement.

  • Double Ratchet Algorithm for message encryption and forward secrecy.

  • AES-256 for symmetric encryption of message content.

  • HMAC-SHA256 for message authentication.

  • Curve25519 (Elliptic Curve) for public-key cryptography.

2. Key Types Used

Each device generates and stores these keys:

Key Type Purpose
Identity Key Long-term Curve25519 key pair identifying the user
Signed Prekey Medium-term Used in initial key exchange; signed with the Identity Key
One-Time Prekeys Short-term Single-use keys to support asynchronous messaging
Session Keys Ephemeral Used to encrypt/decrypt message contents

These keys are stored on the WhatsApp server but never include private keys, ensuring that WhatsApp cannot decrypt messages.

3. Session Setup: X3DH Protocol

When Alice wants to message Bob (who is offline), WhatsApp helps Alice get Bob's public keys:

  1. Bob publishes:

    • Identity Key (long-term)

    • Signed Prekey (medium-term)

    • A batch of One-Time Prekeys (used only once)

  2. Alice retrieves these and runs the X3DH algorithm to compute a shared secret.

  3. This secret bootstraps a Double Ratchet session, and the initial message is encrypted and sent to Bob.

  4. When Bob comes online, he uses his private keys to compute the same shared secret and complete the session.

4. Message Encryption: Double Ratchet Algorithm

Once the session is established:

  • A symmetric key ratchet encrypts messages with a new key each time.

  • A Diffie-Hellman ratchet occurs when new public keys are exchanged, refreshing the root key for forward secrecy.

  • This results in perfect forward secrecy (PFS) and future secrecy (post-compromise security).

Each message is independently encrypted with: 

ciphertext = Encrypt(AES-256, message, derived_key)
MAC = HMAC-SHA256(ciphertext, authentication_key)

5. Message Authentication

Each message includes:

  • A message authentication code (MAC) to verify integrity.

  • Optional sender keys in group chats (see below).

If anything is tampered with or keys don’t match, the message will fail to decrypt.

6. Group Chats (Sender Keys Mechanism)

WhatsApp handles groups efficiently:

  1. A sender generates a Sender Key (a symmetric key).

  2. It shares the Sender Key with group members using individual E2EE messages.

  3. Subsequent messages are encrypted with the Sender Key and sent to all members.

  4. This improves performance vs. encrypting separately for each recipient.

The Sender Key is rotated periodically or when members change.

7. Device Safety & Verification

Users can:

  • Compare a 60-digit code or scan a QR code to verify identity keys.

  • If identity keys change (e.g., new phone), WhatsApp can notify the user.

This protects against MITM (Man-in-the-Middle) attacks.

8. Backups Are Not End-to-End Encrypted (by default)

While messages are E2E encrypted in transit, cloud backups (e.g., to iCloud or Google Drive) used to be unencrypted.

However, WhatsApp added an option for encrypted backups in 2021. If enabled:

  • A user-defined password or 64-digit key is used.

  • WhatsApp cannot recover the backup if the key is lost.

🧠 Summary

Feature Technology
Key Exchange X3DH
Message Encryption AES-256 + Double Ratchet
Authentication HMAC-SHA256
Asymmetric Crypto Curve25519
Group Chats Sender Keys
Forward/Future Secrecy ✅
MITM Protection ✅ (user verification)

explain each of the algorithms in more depth

Absolutely — let’s break down each of the core cryptographic algorithms used in WhatsApp's end-to-end encryption in detail. These are the building blocks of the Signal Protocol, which WhatsApp uses.

🔐 1. Curve25519 (Elliptic Curve Cryptography)

📘 What it is:

  • A high-performance elliptic curve designed for fast and secure key agreement.

  • Used for Diffie-Hellman key exchange.

  • Part of the X3DH and Double Ratchet algorithms in Signal.

🔍 How it works:

  • Each user generates a public-private key pair on Curve25519.

  • Two users exchange public keys, and each uses their own private key and the other’s public key to derive the same shared secret.

  • The math behind it is based on elliptic curves over a finite field (specifically F2255−19\mathbb{F}_{2^{255}-19}F2255−19​).

✅ Why Curve25519:

  • Fast, secure, small keys (32 bytes), resistant to timing attacks.

  • Offers 128-bit security.

🔄 2. X3DH (Extended Triple Diffie-Hellman)

📘 What it is:

  • A key agreement protocol used to establish a shared secret between two parties asynchronously (when one is offline).

  • Foundation of session setup in Signal Protocol.

🔍 How it works:

When Alice wants to initiate a session with Bob:

  1. Bob publishes:

    • Identity Key (IK)

    • Signed Prekey (SPK) – signed by IK

    • One-Time Prekey (OPK) – randomly chosen from a pool

  2. Alice uses her Ephemeral Key (EK) and Bob’s keys to compute 3–4 Diffie-Hellman calculations: 

DH1 = DH(Alice_IK, Bob_SPk)
DH2 = DH(Alice_EK, Bob_IK)
DH3 = DH(Alice_EK, Bob_SPk)
DH4 = DH(Alice_EK, Bob_OPk) (if available)

  1. These are combined and hashed to derive a shared secret.

✅ Why it matters:

  • Allows secure communication even if Bob is offline.

  • Protects against identity key replacement attacks with signed prekeys.

🔄 3. Double Ratchet Algorithm

📘 What it is:

  • Used for encrypting actual messages after the initial key exchange.

  • Combines symmetric-key ratcheting and asymmetric-key ratcheting to achieve:

    • Forward secrecy

    • Post-compromise security

🔍 How it works:

  • Every time a message is sent, it advances the symmetric ratchet (a new key is derived from a previous one).

  • When new Diffie-Hellman key pairs are exchanged, the asymmetric ratchet is used, refreshing the base key (like resetting the "root" of the key tree).

Key flow:

Root Key → Chain Key → Message Keys

Each message gets its own unique Message Key.

✅ Benefits:

  • Even if one message key is compromised, others remain secure.

  • If a device is compromised, the conversation recovers automatically after the next key exchange.

🔑 4. AES-256 (Advanced Encryption Standard, 256-bit)

📘 What it is:

  • A symmetric-key block cipher standardized by NIST.

  • Encrypts the actual content of messages (plaintext → ciphertext).

🔍 How it works:

  • Works on 128-bit blocks.

  • Uses a 256-bit key for encryption.

  • Performs 14 rounds of transformations: substitution, permutation, and mixing of the data.

In WhatsApp, this is usually combined with cipher block chaining (CBC) or Galois/Counter Mode (GCM) to support authentication.

✅ Why it's used:

  • Strong, fast, and widely trusted.

  • Resistant to brute-force attacks with proper implementation.

✅ 5. HMAC-SHA256 (Hash-based Message Authentication Code)

📘 What it is:

  • A MAC (Message Authentication Code) built from the SHA-256 hash function.

  • Ensures integrity and authenticity of messages.

🔍 How it works:

Given:

  • A secret key

  • A message

It produces:

  • A fixed-length output (256 bits) that verifies the message hasn't been tampered with.

The sender generates the HMAC, and the receiver recalculates it using the same key. If the MACs match, the message is trusted.

✅ Why HMAC-SHA256:

  • Very hard to forge.

  • Used to detect both accidental changes and malicious tampering.

💬 6. HKDF (HMAC-based Key Derivation Function)

📘 What it is:

  • A secure way to derive multiple cryptographic keys from a single shared secret.

🔍 How it works:

Takes an input key material (IKM) and produces output key material (OKM) in a structured and secure way using HMAC.

In Signal:

  • It’s used to generate:

    • Root Key

    • Chain Keys

    • Message Keys

✅ Why:

  • Prevents key reuse.

  • Ensures that derived keys are independent and random-looking, even if the initial secret has some structure.

🧠 Summary of Each Algorithm

Algorithm Purpose Role in WhatsApp / Signal Protocol
Curve25519 Public-key cryptography Key exchange (X3DH, DH ratchets)
X3DH Asynchronous key agreement Establish session keys
Double Ratchet Forward & future secrecy Message-level key updates
AES-256 Symmetric encryption Encrypts message content
HMAC-SHA256 Message authentication Ensures integrity
HKDF Key derivation Produces encryption keys

Isn't this too complicated?

Yes — it is complicated, and that’s actually a good thing when it comes to cryptography.

But here’s the key insight:

The complexity is under the hood.
As a user, you never see it — it just works in the background to keep your chats safe.

🔍 Why is it so complex?

Because the goals of secure messaging are ambitious:

Goal Why it's hard
🔐 End-to-end encryption No one but sender & receiver can read messages
🔄 Forward secrecy Old messages stay safe if keys are stolen today
🔁 Future secrecy Future messages stay safe even if your device is hacked now
👥 Group messaging Needs to scale encryption securely across many users
🕒 Offline delivery Messages can be sent to users who are offline
📱 Multi-device support One user can have multiple linked devices securely

All of that requires a mix of advanced algorithms, like the Double Ratchet, X3DH, and Curve25519.

🤝 But for users, it’s simple:

  • ✅ You open WhatsApp.

  • ✅ You send a message.

  • ✅ Only your recipient can read it.

  • 🔒 WhatsApp, hackers, governments — no one else can.

And you didn’t need to know any math or cryptography to make that happen — just install the app and chat.

🧠 TL;DR: Yes, the protocol is complex — and it has to be — but the user experience is intentionally simple and safe.

Is it a job for a single programmer?

No — building a secure end-to-end encrypted messaging system is definitely not a job for a single programmer.

Here's why:

🧠 It Requires a Team With Multiple Specialties:

Role Responsibilities
Cryptographer Designs and reviews the security protocols (e.g., Signal Protocol, key exchange)
Backend Engineer Builds and maintains the server infrastructure (message relaying, key storage)
Frontend/Mobile Developer Implements the encryption logic on iOS, Android, desktop
Security Engineer Tests for vulnerabilities, handles key management, performs audits
Product Designer Ensures security features (like key verification) are usable and clear
QA & Test Engineer Simulates real-world usage, tests multi-device sync, ensures reliability
DevOps/SRE Manages deployment, secure backups, monitors infrastructure for attacks

📊 The Scale Involved

Even if you got the cryptography right, you’d still need to:

  • Handle millions of concurrent users

  • Deliver messages across countries and devices

  • Manage group chats, voice/video calls, file attachments

  • Keep everything backward-compatible and resilient to attacks

This takes months or years of coordinated work — and ongoing maintenance.

🛠️ Example: Signal (the app)

  • Signal was started by Moxie Marlinspike, a cryptographer and programmer.

  • But it eventually became a foundation-backed project with a dedicated engineering and security team.

  • WhatsApp, which adopted the Signal Protocol, is developed by Meta, with dozens of engineers just on messaging security.

⚠️ Doing It Alone = Dangerous

Security is one area where:

  • "Almost correct" = totally broken.

  • A single mistake (e.g., weak key storage, improper randomness, timing leaks) can expose all user data.

If a solo dev builds it, it must be:

  • Open-source

  • Audited by experts

  • Extremely limited in scope

✅ So, What Can a Single Programmer Do?

  • Implement a basic encrypted chat prototype using existing libraries (e.g., NaCl, libsodium, OpenSSL).

  • Build a learning project to understand the principles.

  • Contribute to open-source secure messaging apps (like Signal, Session, Matrix/Element).

  • Avoid writing new crypto — use well-tested libraries and protocols.
